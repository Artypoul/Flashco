# Flashco v0.9.3 source inventory

This is a **provisional transfer inventory**, not evidence of an implemented or tested upgrade. The complete per-path matrix, object modes, Git object IDs, initial dispositions, Android move mapping and merge-probe results are in [the JSON inventory](2026-11-19-v0.9.3-inventory.json). A gitlink's object ID identifies a commit, not a blob. Initial classifications are triage, not approved final per-file resolutions; review deletions, renames, generated files and semantics explicitly.

The union is 1,668 raw paths from complete `git ls-tree -rz` trees. Against v0.9.0, `git diff --no-renames` finds Flashco 128 additions, 45 deletions and 712 modifications (885), and donor 184 additions, 129 deletions and 648 modifications (961). The donor range contains 42 commits. v0.9.0 is a donor ancestor, but **not** an ancestor of Flashco HEAD: the actual common ancestor is `4b59eca853778d4e7be3de26589252889c899bc5`. A normal Git merge would use that older ancestor and is unsuitable as the intended release-to-release content comparison. Supply v0.9.0 as an explicit synthetic content base; do not assert that a content import restores donor ancestry.

Git detects 38 Android source moves from `com/follow/clash` to `com/follow/flashco`, including `FlClashApplication.kt` to `FlashcoApplication.kt`; see the JSON for each pair. Align those paths and normalize package and application-class names in temporary comparison copies before doing content merges. This is not permission for a global substitution: application IDs, public actions, resource references, signing, persisted paths and platform IPC must retain their intended Flashco compatibility. Donor also moves paths independently, notably `NetworkObserveModule.kt` to `NetworkObserver.kt`; this requires a separate semantic mapping and is not covered by the Android path probe.

The probe uses `git merge-file` for files present and changed on both sides, aligning the 38 detected Flashco Android moves and replacing only `com.follow.clash` and `FlClashApplication` in temporary base/donor copies for those paths. It reports **353 textual conflicts and 98 textual clean merges**. It includes generated/instruction paths where eligible and excludes additions, deletions, binary data, gitlinks and independently renamed donor destinations. Thus these are neither all conflicts nor a safe automatic merge; a clean text merge can still break a product contract. Per-file probe results are in the JSON. Path dispositions have 529 manual-adaptation entries, 385 donor candidates, 321 preserve-Flashco entries, 363 identical entries, 38 generated/lock entries, 30 instruction entries and two gitlinks; categories are path-level and overlap neither one another nor probe counts.

The initial disposition matrix uses object/mode comparisons and broad path categories; it is not a comprehensive semantic assessment of each file. In particular, an unchanged upstream path may still need adaptation when another file changes its contract. Optional checkpoint objects are not required for reproducibility; this inventory does not claim to have verified their remote availability. CI, generation, builds, tests, releases and runtime behavior were not run for this documentation-only inventory. `docs/` is ignored in this checkout, so an eventual authorized commit must explicitly add the two inventory files; their presence alone does not make them tracked.

## Publication format

The JSON index uses schema version 2 for bounded GitHub transfers. Its `metadata` preserves the complete original inventory metadata, including the original schema version. `path_parts` lists ordered JSON arrays containing all 1668 original path records, with entry counts and SHA-256 hashes. `probe_parts` similarly preserves the ordered mechanical-merge probe records. Concatenating `path_parts` as `paths` and `probe_parts` as `metadata.mechanical_merge_probe.files` reconstructs the original inventory without data loss. Logical equality against the original inventory was checked before publication; application source is unaffected.
