# Flashco — требования продукта

Этот документ фиксирует подтверждённые требования Артёма к Flashco. Он дополняет технические правила в [AGENTS.md](AGENTS.md), но не заменяет их. Секреты, токены, ссылки подписок, приватные ключи и персональные сетевые журналы в этот файл и в репозиторий не добавляются.

## Назначение

Flashco — простой многоплатформенный клиент прокси на Flutter с ядром mihomo / Clash.Meta. Основной пользовательский сценарий — открыть приложение, импортировать подписку, подключить туннель и пользоваться интернетом без ручной настройки сложного профиля.

Поддерживаемые платформы: Android, Windows, macOS и Linux. Персональные сборки сейчас предназначены прежде всего для Android и Windows.

## Персональные сборки

- GitHub Actions должны принимать обязательный ручной input `subscription_url`.
- Значение передаётся в сборку через `BOOTSTRAP_SUBSCRIPTION_URL` и не записывается в репозиторий.
- Android-сборка выпускает APK, который загружается как артефакт workflow.
- Windows-сборка выпускает EXE и ZIP; оба файла загружаются как артефакты workflow.
- В сборках должны сохраняться TUN, автоматическая маршрутизация, автозапуск и остальные персональные значения по умолчанию.
- Артефакты должны быть доступны для скачивания из завершённого запуска workflow.

## Поведение первого запуска

При корректной подписке персональная Android/Windows-сборка один раз:

- импортирует и сохраняет подписку;
- выбирает профиль и запускает подключение;
- включает светлую тему и русский язык;
- включает автозапуск приложения и подключения;
- включает TUN, `auto-route` и строгую маршрутизацию;
- оставляет системный прокси выключенным и запрет обхода VPN включённым;
- сохраняет последующие ручные изменения пользователя.

Повторный запуск не должен дублировать подписку. Если пользователь удалил профиль, приложение не добавляет его заново автоматически.

## Обновление подписок

- Новые URL-профили на Windows и Android получают включённое автообновление с интервалом 10 минут.
- Интервал сохраняется в настройках каждого профиля и редактируется в его карточке. Планировщик использует это значение, включая повтор после ошибки загрузки; изменение интервала или отключение автообновления сразу пересчитывает расписание.
- При обновлении приложения старое суточное значение URL-профилей однократно переносится на 10 минут. Другие интервалы, выключенное автообновление и остальные настройки сохраняются. После переноса пользователь может снова выбрать суточный интервал.
- При запуске и возвращении в приложение просроченные подписки проверяются сразу. На Android точное выполнение по времени при приостановленном или закрытом ОС приложении не гарантируется.
- Общий код профилей используется обеими персональными сборками без отдельных принудительных значений в workflow.

## Маршрутизация и правила

- Обычный публичный трафик должен проходить через TUN и выбранный прокси-профиль.
- Российские домены и IP должны идти напрямую вне TUN и прокси (`DIRECT`).
- Для этого на новой установке создаются широкие правила `GEOIP,RU,DIRECT` и `DOMAIN-SUFFIX,ru,DIRECT`.
- Адресные правила для конкретных российских сервисов также могут оставаться как явно заданные исключения.
- Весь остальной публичный трафик должен идти через TUN и выбранный прокси-профиль.
- Правила начальной установки создаются один раз только при создании новой базы данных.
- Существующие базы и сохранённые пользовательские правила не переписываются и не очищаются при каждом запуске.
- Приватные локальные сети могут обходить TUN согласно настройке `bypassPrivateRoute`; это не должно превращаться в обход публичных доменов.
- Внешний API по умолчанию закрыт.

## Главный экран и настройки

- На простом экране одна большая кнопка подключения.
- Добавление конфигурации остаётся компактным.
- Переключатель «самый быстрый сервер» не нужен.
- Режим TUN включён по умолчанию в персональных Android/Windows-сборках.
- Жизненным циклом Core владеют соответствующие платформенные слои: Android — `ServiceState`, desktop — `lib/core/desktop/`. UI не становится вторым источником истины для start/stop/restart.
- Команды запуска, остановки и перезапуска должны сохранять приоритет последнего намерения пользователя.

## REALITY и ML-KEM

- ML-KEM включён по умолчанию для REALITY-нод, включая xHTTP и gRPC. Значение хранится в общей настройке `PatchClashConfig.realityMlkemEnabled` и доступно в сетевых настройках.
- Профиль наследует общую настройку либо сохраняет своё включение/отключение в `ProfileOverrides.realityMlkemEnabled`. Отдельная нода может переопределить настройку профиля через `ProfileOverrides.realityMlkem`.
- При формировании рабочего конфига используется приоритет: выбор ноды → настройка профиля → общая настройка. Обновление подписки и перезапуск приложения сохраняют пользовательские значения, включая явное отключение.
- Переименование ноды в подписке не сбрасывает сохранённый выбор; он привязан к адресу, порту, транспорту и SNI.
- Обычные TLS-ноды без REALITY не изменяются.
- В `personal-windows.yaml` перед упаковкой EXE/ZIP и в `personal-android.yaml` перед сборкой APK проверяются сохранение настроек ML-KEM, наследование в профилях и обновление подписки.

## Восстановление соединения

- Общие настройки `autoReconnect`, `autoFailover` и `reconnectInterval` хранятся в `PatchClashConfig`; профиль может наследовать их или сохранить свои значения в `ProfileOverrides`.
- Начальные значения: восстановление и переключение включены, интервал 15 секунд. Интервал редактируется от 1 до 3600 секунд, URL проверок берётся из существующей настройки проверки задержки.
- При включённом переключении группы выбора с прокси получают `fallback`, фоновые проверки (`lazy: false`) и сохранённый интервал в рабочем конфиге. Имена групп, участники и исходный файл подписки сохраняются. Группы с явными DIRECT/REJECT-политиками не преобразуются.
- Выбранная вручную нода используется, пока доступна; при недоступности ядро выбирает доступную альтернативу. Это работает в ядре на Windows и Android, включая свёрнутый Android UI.
- Восстановлением процесса на Windows управляет существующий lifecycle через `CoreAction`, сервисом Android — `ServiceStateMachine`. Ручная остановка отменяет повторные попытки; отзыв разрешения VPN также останавливает восстановление Android.
- Обновление подписки сохраняет явное отключение и настройки интервала. Без доступных нод соединение не переключается на DIRECT.

## Safe в меню «Прокси»

- После `Fastest` находится дополнительная вкладка `Safe` с теми же карточками нод. Пункт выбора пары из редактора профиля удалён; общее устройство интерфейса сохранено. В списочном виде используются те же элементы выбора Safe.
- Safe доступен изначально, без отдельного выключенного переключателя. Внутри автоматические проверки и переключение работают всегда. Открытие вкладки только показывает её; нажатие карточки выбирает ноду и режим Safe. Обычный выбор в PROXY/Fastest выводит из Safe, сохраняя его пару на будущее. Прямой режим остаётся прямым.
- Над карточками выбирается назначение: «Основная нода» или «Резервная нода». Изменение сразу сохраняется в текущий профиль и применяется, без второго сохранения профиля. Указанная резервная нода отличается от основной; до её явного выбора резерв выбирается автоматически из остальных доступных нод профиля.
- Явная пара использует только две выбранные ноды: основная → резервная → возврат к основной после восстановления. Если обе недоступны, третья нода или DIRECT не подставляются. Рамка карточки обозначает выбранную роль, отметка ядра — текущую ноду по результатам проверок.
- Настройка хранится отдельно от подписки в `ProfileOverrides.nodeFailover`; сохраняется после обновления, переименования нод и перезапуска, включая восстановление Android-сервиса. Старый формат пары переносится с сохранением ключей. Ключи определяются адресом и транспортом; страны, имена конкретных серверов и IP в код не зашиваются.
- Область применения определяется итоговыми правилами профиля, включая добавленные правила и переопределение MATCH; глобальный режим также направляется через Safe. Исходная подписка не переписывается. Неактивный Safe не изменяет обычные группы, активный вход в Safe не допускает обхода пары через соседние ноды родительской группы.
- Интервал наследуется из настроек восстановления профиля или приложения (изначально 15 секунд, редактируется), URL — из общих настроек проверки задержки. Настройки восстановления процесса Windows и сервиса Android сохраняют прежних владельцев lifecycle.
- Отсутствующая нода остаётся в сохранённой паре с предупреждением; доступная половина продолжает работать. Ошибка применения показывается пользователю; сохранённый выбор не выдаётся за подтверждённое подключение.
- Внешние провайдеры без встроенного списка и inline-провайдеры с преобразованиями или общим dialer не предлагаются для пары. Для встроенных нод сохраняются параметры и однозначные имена даже при совпадениях исходных названий.

## Приватность и соглашение

- Firebase Analytics и Crashlytics удалены; локальное восстановление после сбоев сохраняется.
- Проверка качества IP через внешние сервисы остаётся.
- QR-сканер Google ML Kit остаётся; возможная обработка диагностики раскрывается в соглашении.
- Соглашение принимается одной кнопкой «Согласен», без обязательной прокрутки и ввода фразы.
- В «О приложении» и соглашении указывается бесплатный некоммерческий продукт, созданный ради юмора.
- Упоминания донора удаляются из пользовательского текста, лицензии компонентов сохраняются.

## Рабочие доступы и маршрутизация SSH

- Локальная папка SSH организуется по папкам проектов, источников или задач.
- В папке SSH поддерживается `Agent.md` с кратким маршрутом: где искать конфигурации, ключи и доступы.
- Рабочие алиасы: `mildred-prod` и `pg-service-prod`.
- Для `pg-service-prod` используется путь ключа `pg/codex_pg_node_20260727`.
- Для `mildred-prod` сохраняются пользователь и ключ по умолчанию.
- Адреса production-серверов, секреты и содержимое ключей не хранятся в репозитории.

## GitHub и рабочий процесс

- Перед изменениями сверяются `AGENTS.md`, `.agents/project.md`, `.agents/commands.md`, `.agents/rules.md` и актуальное состояние Git.
- Для значимых изменений проверяются код, тесты, workflow и фактический diff.
- Commit, push, PR, merge и deploy выполняются только по отдельной явной команде.
- PR без слова `draft` оформляется Ready for review.
- После новых правок нельзя ссылаться на старые результаты проверок; проверки выполняются заново для актуального diff.

## Критерии готовности

Изменение считается готовым, когда:

1. поведение соответствует разделам выше;
2. новые установки получают широкие российские `DIRECT`-исключения только для российских доменов и IP;
3. существующие пользовательские настройки не переписываются без отдельного решения;
4. Android/Windows workflow принимают `subscription_url` и публикуют ожидаемые артефакты;
5. доступные проверки прошли, а недоступные инструменты явно указаны;
6. в финальном отчёте разделены локальные изменения, commit/push/PR/merge/deploy и read-only проверки.
